Core idea
CodexMesh is not “another chat”. It is a fact engine: it pinpoints where logic lives, how it connects, and what to inspect next — then your agent produces the final answer using the LLM you already have.

Why CodexMesh

Most AI coding assistants fail in the same ways: wrong file, shallow understanding of system flow, and answers without evidence. CodexMesh solves this by building a durable structure of your codebase (graphs + indexes) and exposing it through MCP tools, so agents can retrieve the right context deterministically and link every claim to the exact lines responsible for the behavior.

Hotspots: what they are and how they’re computed

Hotpoints are structural risk / complexity centers in your code graph: areas that attract changes, propagate failures, and create expensive debugging paths. They help agents and humans prioritize where to look first.

What is a hotspot?

A node (file/symbol/module) with outsized influence: high fan-in/out, centrality, or proximity to cycles and critical paths.

fan-in/outcentralitycycles

How it’s scored

Typical score mixes: degree metrics, call/import weights, cycle proximity, and graph reachability across key entrypoints.

weighted edgesreachabilityranking

Why it helps

Hotspots guide impact analysis: “change X → what breaks”, “where to add tests”, “where refactors pay off most”.

impacttestingrefactor ROI
Hotspot explain (agent-friendly) why this node matters 
# A “get_hotspot” style output should include:
- score + breakdown (signals)
- top callers / callees / importers / dependents
- closest cycles and paths to entrypoints
- evidence spans for the edges that drive the score

JSON Flows: deterministic tool orchestration for agents

JSON Flows are predefined, machine-readable workflows that describe how to call tools to answer a class of questions. They make agent behavior more reliable, reproducible, and easy to audit.

Why flows exist

Agents can follow a proven plan: which tools to call, in what order, with what limits, and what to store as evidence.

deterministicreproducibleauditable

Benefits in practice

Less wandering and fewer tokens: flows choose the minimal evidence needed, making local LLMs feel faster and more accurate.

token efficiencyfewer round tripshigher signal

Enterprise advantage

Flows make tool usage governable: policies can enforce max depth, max snippets, no sensitive folders, and logging requirements.

policylimitsgovernance
Example flow shape (illustrative) JSON 
{
  "name": "Trace feature execution",
  "goal": "From a user-facing entrypoint to the data layer",
  "steps": [
    {"tool": "detect_entrypoints", "args": {"kind": "web", "limit": 10}},
    {"tool": "build_call_graph", "args": {"root": "$.step0.top[0].id", "depth": 3, "max_nodes": 800}},
    {"tool": "find_path", "args": {"from": "$.step0.top[0].id", "to": "$.step1.sinks[0].id"}},
    {"tool": "read_span", "args": {"path": "$.step2.edges[0].meta.file", "start": "$.step2.edges[0].meta.line_start", "end": "$.step2.edges[0].meta.line_end"}}
  ],
  "outputs": ["evidence_spans", "subgraph", "paths"]
}

Web UI vs MCP: why they are not the same

CodexMesh ships with a web control plane for configuration, observability, and convenience. MCP is the integration interface for agent systems. They solve different problems and can be deployed differently.

MCP = tool protocol

MCP exposes tools over a standardized interface so external agents can orchestrate analysis. MCP can run fully without any LLM.

LLM-agnosticportableagent-ready

Web UI = control plane

Web UI is for human configuration and visibility (projects, indexes, providers, settings). It can optionally include LLM-driven review features.

configurationobservabilityadmin UX

Why Web may need LLM (optional)

If you enable web “review/chat” features, the web layer may integrate LLM providers. MCP itself still does not require LLM.

optionalprovidersseparation
Deployment model clean separation

- runs locally/on-prem
- builds graphs/indexes
- returns structured tool outputs + evidence

Web UI (control plane):
- config + health + inspection
- optional LLM-assisted review features (if enabled)
- not required for external agents to use MCP

Security & Privacy (Enterprise-friendly by design)

CodexMesh is designed to keep source code under your control. It runs locally/on-prem as an MCP tool server and exposes read-only analysis tools. Your agent decides if an LLM is used and which provider is allowed — including fully local models.

Enterprise checklist (what security teams usually care about) practical
  • Data residency: run MCP on developer machines or inside your VPC/on-prem infrastructure.
  • LLM policy control: choose cloud providers or local LLMs; external calls are under your agent’s control.
  • Minimize what leaves the machine: send only the necessary snippets/line ranges (context packs), not entire files.
  • Read-only posture: analysis tools can stay non-mutating to reduce risk and simplify approvals.
  • Operational predictability: limits, ignore rules, and degraded mode prevent “surprise” resource spikes.

Performance: bridging LLM speed gaps with deterministic context

Local LLMs may be slower than cloud models. CodexMesh compensates by reducing the amount of text the LLM must process and minimizing back-and-forth: it delivers the right code fragments and the right relationships, quickly, in a structured way.
